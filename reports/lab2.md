# 1. 简单总结你实现的功能（200字以内，不要贴代码）。
1. 重写 sys_get_time
    先获取时间值结构体 ts0 ， 再仿造 translated_byte_buffer 函数，再通过封装的 copy_to_user 函数找到指针 ts 所指的数据所在物理页帧以及偏移位置，将 ts0 对应位置的数据以切片的形式复制上去。
2. 重写 sys_trace
    > 在读取（trace_request 为 0）时，调用封装的函数 read_byte_from_user 尝试寻找 id 对应的物理页帧以及对应的偏移位置，若找到则判断对应 PTE 是否可读以及在 U mode 下可见，若是则读入一个 u8 类型数据并返回，其他情况都返回 -1 。
    > 在写入（trace_request 为 1）时，与读取类似，调用 write_byte_to_user 尝试寻找 PTE 并判断 PTE 是否同时为可读、可写以及 U mode 可见（必须同时为可读可写，这是 RISC-V 中对可写 PTE 标志位的规定， 单独的可读属于保留类型），若正确则写入一个 u8 类型数据并返回 0 值，否则返回 -1 。
3. 实现 sys_mmap 与 sys_mumap
    > sys_mmap 的实现：先找出覆盖申请范围的 VPN ，进行给定条件的判断，若判断皆通过则对 port 的数值进行分析，获得标志位后调用 MemorySet 的 insert_framed_area 将申请的内存作为新的段加入用户地址空间。
    > sys_unmap的实现：同样先找出覆盖申请范围的 VPN ，进行给定条件的判断，若判断皆通过则通过遍历寻找目标范围所在的 MapArea，接着分析 unmap 后可能剩下的两段（头部和尾部）是否已经被完全 unmap ，若没有则收集原 MapArea 中在该区间的信息并作为一个新的段直接 push 入 MemorySet 的 areas 内（这里不用 insert_framed_area 是因为它的执行过程中会涉及对 VPN 的翻译以及映射到新的 PPN 上，在翻译这部分会出错， 且这个新 MapArea 只有空白的数据），并在 MemorySet 的 page_table 中解除被 unmap 部分 VPN 的映射。

# 2. 完成问答题。
1. 请列举 SV39 页表页表项的组成，描述其中的标志位有何作用？
答： 一个 SV39 页表项（ PTE ）占 54 字节，其中 [53 : 10] 这 44 位是物理页号，最低 8 位 [7 : 0] 则是标志位，两者间为一个 Reserved Word。其中各标志位含义如下：
    > 第 0 位（ V 位 ）， 仅当该位为 1 时，页表项才是合法的；
    > 第 1 / 2 / 3 位（ R / W / X 位 ），分别控制索引到这个页表项的对应虚拟页面是否允许读/写/取指；
    > 第 4 位（ U 位 ），控制索引到这个页表项的对应虚拟页面是否在 CPU 处于 U 特权级的情况下是否被允许访问；
    > 第 5 位（ G 位 ），当该位为 1 时，代表该 PTE 是一个 Global Mapping PTE ，即这个 PTE 在所有地址空间都存在。特别地，若 一个非叶 PTE 被标记为 G ，则它下属的所有级别的页都为 global ；  
    > 第 6 位（ A 位 ），记录自从页表项上的这一位被清零之后，页表项的对应虚拟页面是否被访问过；
    > 第 7 位（ D 位 ），记录自从页表项上的这一位被清零之后，页表项的对应虚拟页表是否被修改过。

2. 缺页
    1) Instruction Page Fault, Load Page Fault, Store / AMO Page Fault 。
    2) 发生缺页以后会触发trap，其中各重要寄存器的值： 
        > sstatus ，其中的 SPP 等字段会给出 Trap 发生前CPU 处在哪个特权级（S/U）等信息；
        > sepc ，当 Trap 是一个异常的时候，记录 Trap 发生之前执行的最后一条指令的地址；
        > scause ，描述 Trap 的原因；
        > stval ， 给出 Trap 附加信息；
        > sscratch ，在最开始保存了内核栈的地址，并在处理 Trap 时可作为中介暂时保存 sp（ sp 指向用户栈或内核栈）的地址。该寄存器在处理 trap的过程中有效地辅助了用户栈道和内核栈的切换；
        > satp ，trap 发生后，satp 的值被替换为内核页表的 PPN 。
    3) 好处：
        > 节约内存空间，避免让暂时用不到的数据占用内存从而影响应用执行；
        > 减少应用启动延时，通过减少数据加载量来缩短加载时间；
        > 降低不必要的磁盘 I / O 。
    4) 3 级页表情况下:
        > 只考虑第三级页表，上层页表因数量级差异忽略不计： 10 G / 页面大小 * PTE 大小 = 10 GiB / 4 KiB * 2^3 B =>  20 MiB 数量级。
    5) 按页的大小的倍数将代码段分为若干部分（下文称为“块”），每次加载一个块的大小，当PC 跳转到块中间时（末尾太晚了，会有明显停顿），执行加载操作将下一块加入内存中，等 PC 跳转到当前块的末尾后，同时开始将旧块放回磁盘中， 发生缺页的可能有当前放入的空闲空间无法容纳整块的大小，导致块部分放入，此时可以先就近移动其他块的一个或若干个页面来放入本块的页面。
    6) 页表项的 V 位为 0 ， R / W / X 位可能保留原权限， 其他位与 PPN 可能被用于存储 Swap 位置信息（如磁盘扇区号）。

3. 双页表与单页表
    1) 操作系统的地址部分存储有其他应用空间页表的物理页号，在需要切换时操作系统会将对应应用空间的页号写入 satp 。
    2) 将内核页面相关的 PTE 的 U 位全部置 0 。
    3) 减少 trap 发生后地址空间切换带来的开销，适合于处理高频系统调用的场景。
    4) 发生 trap 以及 task 切换时。发生 task 切换时。
